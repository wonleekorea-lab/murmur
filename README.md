# journaling（MVP）

だらだら喋った今日を、**箇条書きの原本**と**洞察**に変えて積んでいく音声日記。
名前は目的そのまま。ホーム画面では `journaling`。

喋ったものは母岩で、読みたいのはその中に走っている筋 — という見方は、
ロゴと語彙（`origin` / `found`）に残してある。リポジトリ名も `vein` のまま
（変えると URL が変わり、ホーム画面に追加済みのアイコンが切れる）。

画面は横に2面だけ。**左＝話す／右＝記録**。

| 面 | やること |
|---|---|
| 左（既定） | 語が動きまわる中の **アメーバ** を押す → キーボードの🎤で喋る → `keep` |
| 右 | **日ごとの帯**。1日を24時間の1本にして、書いた時刻に点を置く。上に **#洞察** が溜まる（押すと絞り込み） |
| 右・点か行を押す | まとめ（digest）が開く。**まとめを押すと洞察が出る**。`keep` で日記として並ぶ |
| 右上の `▢` | 日記を全部、読める文にしてクリップボードへ。ひらいた1件の右上の `▢` はその1件だけ |
| 右上の `···` | 設定（全部うつす・データの置き場所）。日記の並びの中には設定を置かない |

**触るのは真ん中のアメーバひとつだけ。** 語は触れない（動いているものを狙わせない）。

---

## 左の面で起きていること

3つが同時に、ひとりでに動いている。**操作は増やさない。**

| | |
|---|---|
| 語が回る | 11語が、語ごとに違う楕円・違う速さ・違う向きで漂う。中心そのものもゆっくり流れるので、同じ道を二度通らない |
| 語が入れ替わる | 6.8秒ごとに1語が消え、置いていない語に替わる（32語の中から）。消えるのは、いま focus から遠いもの |
| 問いが変わる | 4.6秒ごとに focus が別の語へ移り、その語の問いに書き替わる。**直近9語には戻らない**ので問いが繰り返さない |

`do` `be` `have` … は日記の入り口になる概念。focus が当たった語の問いが下に出るので、
何も浮かばない日も、勝手に入口が差し出されつづける。
**アメーバを押した瞬間の focus** が、その日記の入口（`seed`）として残る。

focus は**場所で選ばない**。はじめは「画面の下にいちばん近い語」に当てていたが、
そうすると光る語がいつも下にいて、同じ語に何度も戻るので問いが繰り返して見えた。
いまは「最近当てていない語のうち、いま光っている語からいちばん遠いもの」へ渡す。
光は画面のあちこちへ飛び（実測: 横 10〜89%・縦 5〜92%、1回あたり平均334px）、
6分で29語が出る（全32語）。

語同士が重なると読めないので、画面上で近づいたものだけ、そっと押し合わせている
（角度で測ると、楕円が近いところでの重なりを取りこぼす）。近いほど強く、遠いところでは
効かせないので、急に飛ばない。実測で、どこか1組でも字が重なっている瞬間は 1.7%。

### アメーバ

真ん中は円ではない。9点の半径がそれぞれ違う周期で伸び縮みする閉じた曲線を、
Catmull-Rom でつないで毎フレーム描き直している。**平らな墨1色**で、
グラデーション・影・広がる輪は使わない。生きている感じは、輪郭の歪みだけで出す。

動かさない設定（`prefers-reduced-motion`）のときは形を止め、問いだけ7秒ごとに移す。
記録の面にいるとき・喋っている最中・アプリを閉じているあいだは、描画そのものを止める。

## 色

**紙と墨だけ。** 地は温かい白（`#F4F2EE`）、字と形は墨（`#14120F`）。
色で差を付けず、濃さ・大きさ・余白で差を付ける。
ember（黒地）や aloud と並べたときに、ひと目で違う面だと分かる地にしてある。

## ロゴ

平らなアメーバを、脈が1本斜めに貫く。**脈はアメーバの中では地の色に反転する。**
声（かたち）と、その中に走っている筋（洞察）を、線1本で重ねた形。
`tools/make-icons.py` の生成物で、記録面の見出しにも同じ図形を置いている。

アイコンの絵を変えるときは、**必ずファイル名の `v` を上げる**
（iOS Safari は URL ごとに長期キャッシュするので、同じ名前のままでは古い絵が残る）。

## 右の面（記録）

面はこの順で、上から下へ**1本の背骨**になっている。

```
[ ロゴ  journaling                    ▢  ··· ]   ← 見出し（動かない）
[ 4 days   3 in a row   7 insights          ]
[ #洞察 #洞察 #洞察 …                       ]   ← 横に1行で流す
[ 0    6    12    18    24 ]────────────────    ← 時刻の目盛り（据え置き）
   2026年9月                                     ← 月の区切り
   今日 9/10 ────────────────────  まだ
   昨日 9/9  ──●───────○──────○     3
     07:12  まとめ…  #洞察
     13:40  まとめ…
   — 3日 —
   2026年8月
```

見出し・数・#洞察・目盛りは動かない（据え置き）。スクロールするのは日の帯だけ。
**目盛りと帯は左右の端をそろえてある**ので、上の数字がそのまま下の点の時刻になる。

**日ごとの帯**。上に時刻の目盛り（0・6・12・18・24）を1本だけ置き、
その下に日を新しい順に積む。1日が1本の線で、書いた時刻の位置に点が乗る。

- **1日に何度でも書ける前提**。点が増えていくことが、その日の線を見れば分かる
  （2件以上ある日は、右端に件数を出す）
- 点は **●=保存した / ○=まだ**。整形中の点はゆっくり点滅する
- 線の下に、その日の日記を時刻順に並べる（時刻・まとめ・`#洞察`・状態）。
  点でも行でも、押せば開く
- **書かなかった日は1行にまとめる**（`— 3日 —`）。詰めて並べると間が空いたことが見えず、
  1日1行で並べると空白ばかりになるため
- `#洞察` で絞ると、その見出しを持つ日だけが残り、該当する点に輪が付く
- **月をまたぐと区切りが入る**（`2026年9月`）。長くなったときの背骨
- **今日まだ書いていない日も、空の線と `まだ` を出す**。空いた1本があることが、書く理由になる

## うつす（copy）

日記はこの端末の中にしか無いので、外へ出す道をひとつだけ持たせている。

- 記録面の右上の **`▢`**：全部を1つの文にしてクリップボードへ（押すと `▢` が塗りつぶしになる）
- ひらいた1件の右上の **`▢`**：その1件だけ
- **各段の右上の `▢`**：`summary` / `found` / `echo` / `spark` / `origin` / `raw` を、その段だけ
- 中身は **まとめ / 原本 / 洞察 / 次の問い / 補足 / 喋ったまま** の全部。日付と時刻と入口の語も付く
- `navigator.clipboard` は https か localhost でしか使えないので、
  使えないときは選択して写す昔の道（`execCommand`）に落ちる

## 設定（`···`）

毎日見るものではないものを、日記の並びから外に出すためだけの面。中身は2つだけ。

| | |
|---|---|
| `copy` | 日記を全部うつす（件数を出す） |
| `data` | どこに在るか・消えるとどうなるか |

以前ここに `key`（Claude の鍵）があったが、**鍵の概念そのものをやめた**ので消えている。

## 1件の面（6段）

1件をひらくと、上から下へこの順に置く。**上から順に読めば、次に喋りたくなる**という並びにしてある。
各段の右上に **`▢`** があり、その段だけを写せる。

| 段 | 中身 | なぜここに在るか |
|---|---|---|
| `summary` | **話したことの箇条書き**。語で寄せた**かたまり**ごとに、空きを入れて置く | 面の頭。話の切り替わりが見える。ここだけ読めば足りる |
| `#洞察` | その日の見出し | 溜まっていくのが見える |
| `found` | **気づき**。本人が「気づいた／つまり／結局…」と言った行をそのまま | 発見は作らない。**言った瞬間を拾い返す**だけ |
| `echo` | **前に自分が言っていたこと**。同じ語を喋った過去の日を、日数つきで | 唯一の事実の段。溜まるほど効く。押せばその日記が開く |
| `spark` | **起爆剤**。①過去に同じ語を喋っていたか ②どんな言い方をしたか（決意／断定／詰まり／気づき）で選んだ問いを3つ | 答えではなく、次に喋り出す口を開けるためだけの段 |
| `origin` | 原本（全部の行） | 一次情報。解釈が混ざる前の自分 |
| `raw` | 喋った文字そのまま | 消さないための段。あとから何にでも戻せる |
| `ask ai` | **AIに読ませる文をうつす**（指示つき） | 解釈だけは手元の規則では作れない。ここだけ外に出す |

`summary` は行を語で寄せて、かたまりのあいだに空きを入れる。
**見出しは、そのかたまりで2回以上・3字以上出てくる語があるときだけ付ける。**
1回しか出ない語を見出しにすると「行抜」のような切れ端が出て、かえって読めなくなる
（実際に出たのでやめた）。要約はしない。言い換えると本人の言葉ではなくなる。

`echo` は、この日記の語と過去の日記の語を突き合わせて、共通の語が多い順に3件まで。

`spark` は当てずっぽうに型を選ばない。この順に見て、当たった型だけを使う。

1. **過去に同じ語を喋っていたか** →「『Codex』は6日前にも言っていた。あれから何が動いた？」
   ここは事実なので、いちばん刺さる
2. **言い方の型** → 決意（したい・やめたい・決めた）／断定（いちばん・べき・だと思う）／
   詰まり（辛い・微妙・うまくいかない）／気づき（気づいた・つまり・結局）
3. どれにも当たらなければ、内容に寄らない問い

同じ日記なら毎回同じものが出る（`id` から選ぶ。毎回変わると落ち着かない）。

## 使う

### 手元で見る

```bash
python3 -m http.server 8930 --directory "vein"
```

`http://localhost:8930/` を開く。

### iPhone に置く（本命）

**https://wonleekorea-lab.github.io/vein/**

上のURLを Safari で開き、共有メニューから「ホーム画面に追加」。
`manifest.json` と `sw.js` があるので、追加後はアドレスバーのない全画面で立ち上がり、
オフラインでも起動する（Sokugan / 好きの種 と同じ形）。ホーム画面の名前は `journaling`。

**https（または localhost）でないと動かない。** `file://` ではキーボードのマイクも
Service Worker も使えない。

### 配信

`wonleekorea-lab/vein` の `main` ブランチ直下を GitHub Pages がそのまま配信する。
`git push origin main` すれば1〜2分で反映される。`.nojekyll` があるのでビルドは走らない。

## 音声

**Web Speech API は使わない。**声は iOS キーボードのマイクキー（Apple のディクテーション）から入れる。
理由は好きの種と同じで、Web Speech API では ①起動のたびにマイクの許可を訊かれ ②開始と終了に音が鳴る。
どちらも iOS 側が出すもので、API からは止められない。

- **音声ファイルは保存も送信もしない**。アプリが受け取るのは確定した文字だけ
- 打っても喋っても同じ欄に入る。喋れない場所ではそのまま打てばいい
- キーボードの高さは `visualViewport` で測り、`--kb` としてページ下の余白に入れる（`100dvh` はキーボードに反応しない）

### 長い文の見せ方

だらだら喋るので、**読ませる字ではなく「入っている」ことが見える字**にしている。
全体が一度に目に入るところまで自分で縮める（20px → 下限 8px）。

実測: 477字で16px、2120字で8px（このとき上が35pxだけ切れ、末尾が見える位置に留まる）。
上端はグラデーションで薄くしてあり、続きが上にあることだけ分かる。

## 組み立て（鍵はいらない）

**AIを呼ばない。鍵（API key）の概念を置かない。外へは何も送らない。**
組み立ては全部この端末の中の規則でやる。だから、この MVP は**解釈をしない**。

やっているのはこの4つだけ。

| | やり方 | 作っていないもの |
|---|---|---|
| 箇条書きにする | 句点で割り、頭の言いよどみを落とし、短い言い直しは前の行にくっつける | 要約・言い換え |
| 気づきを拾う | 気づきの言い方を含む行を、**そのまま**返す | 洞察の生成 |
| 過去とつなぐ | 語を突き合わせて、同じ語を喋った日を出す | 関連の推測 |
| 起爆剤を出す | この日の語を、16通りの問いの型に入れる | 事実・知識の追加 |

### 「ハッとする」はどこから来るか

手元の規則で出せるのは、**並べ替え・拾い返し・突き合わせ・問いの型**まで。
ここから先（矛盾の指摘、前提のすり替えの発見、避けている論点の名指し）は解釈なので、
規則では作れない。作ったふりをすると、外れた見出しや的外れな問いになって、
かえって信用を失う（実際に「行抜」という見出しと、内容とすれ違う問いが出た）。

いま置いてある道は2つ。

| | どこで解釈するか | 要るもの |
|---|---|---|
| `ask ai`（採用中） | 写した文を自分でAIに貼る | 何も要らない。貼る1手だけ |
| 鍵を持つ側を1枚挟む（未着手） | アプリの中で自動的に出る | 置き場（Workers など）＋鍵を外に置く判断＋わずかな費用 |

`ask ai` の文には「気づいていないことを、本人の言葉の矛盾から3つ」まで指示が入っている。
**洞察の質を決めているのはこの指示文**なので、直すのは `core.html` の
`ASK_ONE`（1件用）と `ASK_ALL`（全部用）の2つだけでよい。

## ファイル

| ファイル | 役割 |
|---|---|
| `core.html` | **正本**。CSS・HTML・JS の全部。触るのはここだけ |
| `build.sh` | `core.html` から `index.html` と `artifact.html` を生成する |
| `shell-head.html` / `shell-foot.html` | PWA の外殻（meta、manifest、Service Worker 登録） |
| `index.html` | 生成物。ホスティングに置くのはこれ |
| `artifact.html` | 生成物。`<html>` の外殻を持たない body 相当 |
| `manifest.json` / `sw.js` | ホーム画面追加時の名前・色・アイコン／アプリシェルのオフライン保持 |
| `tools/make-icons.py` | アイコン生成。図案はアメーバを貫く脈（アプリ内のロゴと同じ形） |

編集したら必ず：

```bash
sh "vein/build.sh"
```

`index.html` と `artifact.html` を直接編集しないこと（次のビルドで消える）。

アイコンを描き替えるときは **必ずファイル名の `v` を上げる**（iOS Safari は URL ごとに長期キャッシュする）。
`tools/make-icons.py` の `VERSION` → `shell-head.html` → `manifest.json` → `sw.js` の `CACHE` 名まで揃える。

## データ

- 保存先は **この端末・このブラウザの localStorage**。キーは `murmur_state_v1`（名前を変える前のものを引き継ぐ）
- **サーバへは何も送らない。**AIも呼ばない。アカウントも同期もない
- 前の版で鍵を入れていた場合、起動時に `settings.key` を**捨ててから**保存し直す
- **ブラウザのデータを消すと日記も消える**。Safari の「履歴とWebサイトデータを消去」で消える
- 保存データが壊れていた場合、消さずに `murmur_state_v1_backup_<時刻>` へ退避してから空で立ち上がる
- localStorage が使えない文脈（プライベートブラウズ、埋め込み枠の中）ではメモリ上だけで動き、一度だけその旨を出す

1件の形:

```
{ id, createdAt, day, seed,          // seed = 入口に押した語
  raw, lines[], digest, tags[],
  status }                            // draft → read → kept
```

`found` / `echo` / `spark` は**保存しない**。ひらくたびに組み立てる。
`echo` は日記が増えるほど良くなるので、保存すると古い結果が残ってしまう。

`status` は `draft`（置いたばかり）→ `read`（ひらいた）→ `kept`（`keep` を押した）。
`kept` になったものだけが見出しの数（`insights`）に入る。
`picks` / `asks` / `notes` は旧版（Claudeを呼んでいたころ）の名残で、
残っている日記だけ面の下に出す。新しく作ることはない。

## ことば

画面まわりの語は**英単語1語**に統一する（好きの種と同じ規則）。日本語は、ユーザー自身の声と、
失敗の説明だけに残す。

| 語 | 意味 |
|---|---|
| `press` | 最初の一押し |
| `keep` | 置く（喋り終えて／読み終えて） |
| `close` | 閉じる |
| `clear` | 書きかけを消す |
| `forget` | この日記をそっと消す |
| `found` / `echo` / `spark` | 気づき（言った行） / 前に言っていたこと / 起爆剤 |
| `summary` / `origin` / `raw` | 話したことの箇条書き / 原本 / 喋った文字そのまま |
| `days` / `in a row` / `insights` | 日数 / 連続 / 見出しの数 |
| `undo` / `yes` / `retry` | 通知の中の一手 |

## このMVPでやっていないこと

- 検索、クラウド同期、アカウント
- 見出しの手直し・統合（似た概念が別タグで増えたときにまとめる手段がない）
- 週・月のまとめ（溜まった日記を横断して読む面）
- リマインド（夜に「今日を喋る？」と促す通知）
- 音声の保存、Web Speech API による自前の文字起こし
- **AIによる解釈**（洞察の生成・要約・事実の追加）。段を写して外のAIに渡す形にしている

## 既知の制約

- 2000字を超えると 8px でも収まりきらず、上が少し切れる（末尾が見える位置に留まる）
- `found` は言い方で拾うので、気づきを「気づいた」と言わずに喋った日は空になる
- `echo` は語の一致だけを見るので、同じことを別の言い方で喋った日はつながらない
- `spark` の問いは型なので、内容にぴたりと合わないことがある（合わない問いも口は開く、という前提）
- 語の並びは重なりを完全には避けられない。押し合わせているだけなので、ときどき一瞬すれ違う（実測1.7%）
- 帯は今日から最も古い日まで全部の日を見るので、間が空きすぎると空き行の計算が長くなる（500日で打ち切る）
