# ひとりごと（murmur / MVP）

だらだら喋った今日を、**箇条書きの原本**と**洞察**に変えて積んでいく音声日記。

画面は横に2面だけ。**左＝話す／右＝記録**。

| 面 | やること |
|---|---|
| 左（既定） | `do` `be` `have` … の語の中に **◯** が潜んでいる。◯ を押す → キーボードの🎤で喋る → `keep` |
| 左・語を押す | その語が入口の問いになる（「今日、実際に何をした？」）。喋る前の呼び水 |
| 右 | 日ごとに日記が並ぶ。上に **#洞察** の見出しが大きさ違いで溜まる。押すと絞り込み |
| 右・カードを押す | まとめ（digest）が開く。**まとめを押すと洞察が出る**。`keep` で日記として並ぶ |

文字は極力置いていない。左の面は語と丸だけで、喋ったあとにはじめて文が出る。

---

## 3段になっている

喋ったものを、性質のちがう3つに分けて持つ。**捨てるのは言いよどみだけ**。

| 段 | 中身 | 誰のための段か |
|---|---|---|
| `raw` | 喋った文字そのまま | 消さないための段。あとから何にでも戻せる |
| `lines` | 箇条書きの**原本**。言いよどみと言い直しを落とし、日本語として読める形にしただけ。**内容の精査はしない** | 一次情報。解釈が混ざる前の自分 |
| `digest` | 3〜5文のまとめ | 読み返す段。頭の中のものが「引き出された」状態になる |
| `picks` / `asks` / `notes` | 洞察・次の問い・知識の補足 | 次の探究に渡す段。まとめを押したときだけ作る |
| `tags` | その日の洞察の見出し（`#列の設計` など） | 溜まっていくのが見える段 |

`digest` を押すまで洞察は作らない。**読み返す**と**掘り下げる**を同じ動作にすると、
毎日どちらもやらなくなるため、別の動作に分けてある。

`tags` は分類名（仕事・健康）ではなく、その日固有の概念にするよう指示している。
分類名だとタグの数が増えず、溜まっていく手応えが出ない。

## 使う

### 手元で見る

```bash
python3 -m http.server 8930 --directory "murmur"
```

`http://localhost:8930/` を開く。

### iPhone に置く（本命）

**https://wonleekorea-lab.github.io/murmur/**

上のURLを Safari で開き、共有メニューから「ホーム画面に追加」。
`manifest.json` と `sw.js` があるので、追加後はアドレスバーのない全画面で立ち上がり、
オフラインでも起動する（Sokugan / 好きの種 と同じ形）。

**https（または localhost）でないと動かない。** `file://` ではキーボードのマイクも
Service Worker も使えない。

### 配信

`wonleekorea-lab/murmur` の `main` ブランチ直下を GitHub Pages がそのまま配信する。
`git push origin main` すれば1〜2分で反映される。`.nojekyll` があるのでビルドは走らない。

## 音声

**Web Speech API は使わない。**声は iOS キーボードのマイクキー（Apple のディクテーション）から入れる。
理由は好きの種と同じで、Web Speech API では ①起動のたびにマイクの許可を訊かれ ②開始と終了に音が鳴る。
どちらも iOS 側が出すもので、API からは止められない。

- **音声ファイルは保存も送信もしない**。アプリが受け取るのは確定した文字だけ
- 打っても喋っても同じ欄に入る。喋れない場所ではそのまま打てばいい
- キーボードの高さは `visualViewport` で測り、`--kb` としてページ下の余白に入れる（`100dvh` はキーボードに反応しない）

### 長い文の見せ方

だらだら喋るので、**読ませる字ではなく「入っている」ことが見える字**にしている。
全体が一度に目に入るところまで自分で縮める（20px → 下限 8px）。

実測: 477字で16px、2120字で8px（このとき上が35pxだけ切れ、末尾が見える位置に留まる）。
上端はグラデーションで薄くしてあり、続きが上にあることだけ分かる。

## Claude（整形と洞察）

整形と洞察に **`claude-opus-5`** を使う。呼ぶのはブラウザから直接
（`https://api.anthropic.com/v1/messages`、`anthropic-dangerous-direct-browser-access: true`）。

鍵は**記録面のいちばん下**に入れる。

- 鍵はこの端末のブラウザの localStorage にだけ残る。リポジトリにも他のどこにも入らない
- 送り先は `api.anthropic.com` だけ。Service Worker は外部オリジンの通信に触らない
- **鍵が無くてもアプリは通しで使える**。整形は手元の規則（文で割り、言いよどみを落とす）に落ち、
  見出しは語の切り出しになる。洞察だけは作らない（作れないものを作らない）
- 呼ぶのは2回だけ。`keep` したとき（整形・effort=low）と、まとめを押したとき（洞察・effort=high）

**未検証:** 鍵を持っていないので、実際の API 応答での動作は確認できていない。
リクエストの形は公式の cURL 例に合わせてある。最初の1件で
「整えた箇条書きが原本らしいか」「見出しが分類名になっていないか」を見て、
ずれていたら `core.html` の `SHAPE_SYS` / `REFLECT_SYS` を直す（プロンプトはこの2つだけ）。

## ファイル

| ファイル | 役割 |
|---|---|
| `core.html` | **正本**。CSS・HTML・JS の全部。触るのはここだけ |
| `build.sh` | `core.html` から `index.html` と `artifact.html` を生成する |
| `shell-head.html` / `shell-foot.html` | PWA の外殻（meta、manifest、Service Worker 登録） |
| `index.html` | 生成物。ホスティングに置くのはこれ |
| `artifact.html` | 生成物。`<html>` の外殻を持たない body 相当 |
| `manifest.json` / `sw.js` | ホーム画面追加時の名前・色・アイコン／アプリシェルのオフライン保持 |
| `tools/make-icons.py` | アイコン生成。図案は「喋ったものが行になる」＝押す丸と右へ伸びる3本の行 |

編集したら必ず：

```bash
sh "murmur/build.sh"
```

`index.html` と `artifact.html` を直接編集しないこと（次のビルドで消える）。

アイコンを描き替えるときは **必ずファイル名の `v` を上げる**（iOS Safari は URL ごとに長期キャッシュする）。
`tools/make-icons.py` の `VERSION` → `shell-head.html` → `manifest.json` → `sw.js` の `CACHE` 名まで揃える。

## データ

- 保存先は **この端末・このブラウザの localStorage**。キーは `murmur_state_v1`
- サーバへは何も送らない（Claude を呼ぶときの本文を除く）。アカウントも同期もない
- **ブラウザのデータを消すと日記も消える**。Safari の「履歴とWebサイトデータを消去」で消える
- 保存データが壊れていた場合、消さずに `murmur_state_v1_backup_<時刻>` へ退避してから空で立ち上がる
- localStorage が使えない文脈（プライベートブラウズ、埋め込み枠の中）ではメモリ上だけで動き、一度だけその旨を出す

1件の形:

```
{ id, createdAt, day, seed,          // seed = 入口に押した語
  raw, lines[], digest,
  picks[{t,d}], asks[], notes[{t,d}], tags[],
  status }                            // draft → read → kept
```

`status` は `draft`（整形済み・まだ読んでいない）→ `read`（洞察が出た）→ `kept`（保存した）。
`kept` になったものだけが見出しの数（`insights`）に入る。

## ことば

画面まわりの語は**英単語1語**に統一する（好きの種と同じ規則）。日本語は、ユーザー自身の声と、
失敗の説明だけに残す。

| 語 | 意味 |
|---|---|
| `press` | 最初の一押し |
| `keep` | 置く（喋り終えて／読み終えて） |
| `close` | 閉じる |
| `clear` | 書きかけを消す |
| `forget` | この日記をそっと消す |
| `found` / `next` / `notes` | 洞察 / 次の問い / 知識の補足 |
| `origin` / `raw` | 箇条書きの原本 / 喋った文字そのまま |
| `days` / `in a row` / `insights` | 日数 / 連続 / 見出しの数 |
| `key` / `save` | 鍵 |
| `undo` / `yes` / `retry` | 通知の中の一手 |

## このMVPでやっていないこと

- 検索、書き出し（`export`）、クラウド同期、アカウント
- 見出しの手直し・統合（似た概念が別タグで増えたときにまとめる手段がない）
- 週・月のまとめ（溜まった日記を横断して読む面）
- リマインド（夜に「今日を喋る？」と促す通知）
- 音声の保存、Web Speech API による自前の文字起こし

## 既知の制約

- 2000字を超えると 8px でも収まりきらず、上が少し切れる（末尾が見える位置に留まる）
- 鍵が無いときの `digest` は箇条書きをつないだだけなので長い。まとめとしては読みにくい
- 洞察の生成は1件ずつ手で押す。まとめて処理する手段はない
